OPTION 7. Issue a Book (Auto 14-day due date)
=====================================================================================
KYA KARTA HAI:
  Kisi student ko book deta hai. Due date apne-aap aaj + 14 din set hoti hai.

KAISE KAAM KARTA HAI:
  1. Student ID aur Book ID lo.
  2. Check: student exist karta hai? book exist karti hai? shelf pe copy hai
     (available_copies > 0)? Koi bhi "nahi" -> error message, kuch save nahi.
  3. issue_date = aaj, due_date = aaj + timedelta(days=14).
  4. INSERT INTO transactions (return_date = NULL, fine = 0)
     -> return_date NULL ka matlab "book abhi student ke paas hai".
  5. UPDATE books SET available_copies = available_copies - 1
  6. commit -> "Issued ... Due Date: YYYY-MM-DD" print.

CODE KAHAN HAI:
  main.py, line 229:  def issue_book()


=====================================================================================
OPTION 8. Return a Book (Auto Rs 5/day fine calculation)
=====================================================================================
KYA KARTA HAI:
  Book wapas leta hai aur late ho to fine calculate karta hai (Rs 5 per din).

KAISE KAAM KARTA HAI:
  1. Transaction ID lo (Option 9 ya 10 se dekh sakte ho).
  2. Transaction + book + student JOIN karke details laao.
  3. return_date pehle se bhari hai -> "already returned" message.
  4. overdue_days = max(0, aaj - due_date)
     fine = overdue_days x 5
  5. UPDATE transactions SET return_date = aaj, fine_amount = fine
     UPDATE books SET available_copies = available_copies + 1
  6. Fine > 0 -> "OVERDUE NOTICE ... Fine Due" warna "Returned on-time".

CODE KAHAN HAI:
  main.py, line 279:  def return_book()

OPTION 11. Data Cleaning & Aggregation Report          [SYLLABUS: Unit 2]
=====================================================================================
KYA KARTA HAI:
  Terminal me ek report print karta hai jo dikhata hai ki raw data ko kaise saaf aur
  summarize kiya gaya. Isme 5 parts hain:
    [1] Raw tables ka size (rows x columns)
    [2] Missing values (return_date ke NULL = active loans) aur duplicate rows
    [3] Cleaning steps (dates convert, days_kept, overdue_days, fine, status)
    [4] Aggregation: department x status pivot table
    [5] Summary statistics (mean, std, min, max...) of days_kept, overdue, fine

KAISE KAAM KARTA HAI:
  load_raw_data() se 4 tables -> isnull().sum() se missing values ->
  get_cleaned_transactions() se clean table -> pivot_table() aur describe().

  Cleaning rules (get_cleaned_transactions ke andar):
    days_kept      = return date (ya aaj) - issue date, minimum 1
    overdue_days   = return date (ya aaj) - due date,   minimum 0
    effective_fine = max(recorded fine, overdue_days x 5)
    status         = Active Overdue / Active On-Time / Returned Overdue / Returned On-Time

OPTION 15. Supply Chain & Logistics Case Study (Region filter)   [SYLLABUS: Self-study Case Study]
=====================================================================================
KYA KARTA HAI:
  Publishers (Mumbai, Ahmedabad, New Delhi, Bengaluru, Chennai, Kolkata) se Pune
  campus tak aane wali book shipments ka analysis.
    1. Region chuno: 0 All, 1 North, 2 West, 3 South, 4 East  (= filtering by region)
    2. Terminal me: total shipments, units, freight cost, on-time delivery gauge,
       average transit days.
    3. DELIVERY STATUS KPIs: Delivered On-Time / Delivered Late / In Transit /
       Delayed In Transit (count aur %).
    4. ROUTES table: har origin city -> km, shipments, avg days, late count
       (= route mapping, table form me).
    5. Dashboard image banta hai: charts/supply_chain_dashboard_<region>.png
       (KPI cards, gauge, route map arrows, status by region, monthly on-time trend,
        courier delay) aur window me khulta hai.

KAISE KAAM KARTA HAI:
  1. get_cleaned_shipments(region): shipments + books JOIN,
       transit_days = delivery (ya aaj) - dispatch
       delay_days   = delivery (ya aaj) - expected, minimum 0
       status       = upar ke 4 me se ek
     phir region filter.
  2. groupby('origin_city') se routes table.
  3. plot_supply_chain_dashboard(region) gridspec se 3-row dashboard banata hai.

  Shipment data kahan se aaya:
    db_setup.seed_shipments() 160 shipments banata hai. Distance haversine_km() se
    (latitude/longitude se asli doori). Expected days = distance/450 + 1.
    India Post aur lambi doori pe delay ka chance zyada rakha gaya hai.
